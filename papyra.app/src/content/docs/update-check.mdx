Papyra has no tracking, analytics or crash reports, and it makes no request to any server its makers run. Without anyone
setting anything up, it makes **one** request of its own, once a day: it looks at GitHub to see whether a newer version is
out. **It is optional.** You can [turn it off](#turning-it-off) with one setting.

## What it does

Your server asks GitHub for the newest release of Papyra, the same page you would open in a browser. If it is newer than
the one you run, admins see a warning icon beside the version in the sidebar, with a popup linking to the release notes.
Other accounts never see it.

The whole client is [`UpdateCheck.cs`](https://github.com/lyfie-org/papyra/blob/main/papyra.api/src/Papyra.Api/Storage/UpdateCheck.cs).

## What it asks

```
GET https://api.github.com/repos/lyfie-org/papyra/releases/latest
```

That is all. The request has no ID, no version number, no processor or system, and nothing about your notes, accounts or
settings. Like any web request, GitHub can see the address your server connects from. Nobody keeps a count of installs,
and there is no server of ours in the loop.

## Turning it off

Set this in your compose file and restart:

```yaml
PAPYRA_UPDATE_CHECK_ENABLED: "false"
```

Papyra then never makes the request, and admins won't see the update notice, so watch the
[releases page](https://github.com/lyfie-org/papyra/releases) yourself. Nothing else in Papyra changes.

## When it asks

- About once a day, a few random minutes later each time, so servers started together don't all ask at once.
- A restart doesn't ask again: Papyra remembers when it last got an answer.
- If GitHub can't be reached, or asks Papyra to slow down, it tries again after 1 hour, then 2, 4 and 6. Nobody sees an
  error.
- A server with no release version (a development build) never asks.
